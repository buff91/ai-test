# Jev / Laya 게임 제어 실습실

게임 화면에서 **관찰 → 모델 판단 → 인터페이스 입력 → 게임 변화**를 확인하는 강의용 프로젝트입니다. 기본 예제는 턴제 RPG 전투(`party`), 레이싱(`racer`), MOBA(`moba`) 세 가지입니다. 모델을 교체해도 게임과 연결 코드는 같습니다.

## 시작

Apple Silicon Mac, Python 3.11 이상, uv가 기준 환경입니다.

```sh
uv sync
./start.sh
```

콘솔에서 게임과 원하는 플레이 방식을 선택합니다. **직접 플레이**는 게임 창에서 사람이 조작하고, **모델 제어 · 게임 데이터**는 내부 상태와 행동 명령을 사용하며, **모델 제어 · 화면 + 키마**는 화면 관찰과 키보드·마우스 입력을 사용합니다. 세 방식은 순서 없이 선택할 수 있고, 모델 제어 옵션을 누르면 실제 연결 설정도 바뀝니다. **응답 시간 비교**는 두 모델 제어 방식에서 사용할 수 있는 별도 설정입니다.

**게임 창 준비**로 창을 열면 모델 연결 없이 직접 플레이할 수 있습니다. 모델 제어를 선택했다면 **게임 연결** 후 실행합니다. 준비한 창은 연결을 끊어도 유지되므로 같은 판에서 두 경로를 바꿔 볼 수 있습니다. 실행 중에는 먼저 중지하고, 연결 방식을 바꿀 때는 연결을 끊습니다. 콘솔을 종료하면 콘솔이 준비한 창도 종료됩니다. 콘솔 상태판은 인터페이스로 받은 상태를 그린 도식이고, 실제 플레이 화면은 별도 게임 창입니다. 키마 모드의 미리보기는 실제 캡처입니다.

- **RPG 전투**: 파티 체력·마나·적의 다음 공격을 보고 공격, 광역기, 회복, 방어, 부활을 선택합니다. 모델이 판단하는 동안 턴은 기다립니다.
- **레이싱**: 차선, 속도, 커브와 장애물을 보고 조향·감속·가속을 선택합니다. 차는 연속 주행하며 가속과 조향을 각각 즉시 바꿀 수 있습니다.
- **MOBA**: W/S로 이동을 시작하고 E로 멈춥니다. 이동 중에도 공격·스킬·라인 전환을 사용할 수 있습니다. 공격은 0.5초, 스킬은 3초, 귀환은 4초의 재사용 시간이 있습니다.

레이싱과 MOBA는 화면 유무와 관계없이 시작·리셋 직후부터 실시간으로 진행됩니다. 모델 판단 중에도 멈추지 않으며, P로 직접 일시정지할 수 있습니다. 화면은 약 30fps, 화면 없는 게임은 60Hz 시계로 움직이고 미니언 교전은 기본 1초마다 처리합니다. 실시간 채점의 기준 행동은 현재 상태를 단순화한 탐색 참고값입니다. 오프라인 사례 생성(`python -m sims cases`)은 재현 가능한 고정 단계 규칙을 사용합니다.

Jev 키는 `JEV_API_KEY` 환경 변수 또는 콘솔 입력칸에 넣습니다. 키는 설정 파일·세션에 저장하지 않습니다. Laya / Laya-MLX는 로컬 모델이며 최초 준비에 다운로드와 시간이 필요할 수 있습니다. 모델 응답 성공, 입력 적용, 지연 예산 만족은 서로 다른 결과입니다.

## 활용 예시

아래 항목은 필요에 따라 골라 사용할 수 있으며, 앞 항목을 완료해야 하는 조건은 없습니다.

1. **직접 플레이**: 게임 창의 키 안내와 버튼으로 행동과 결과를 확인합니다.
2. **인터페이스 관찰**: 콘솔의 상태 설명과 `questions.json`이 모델 입력이라는 점을 확인합니다. 정답은 채점에만 쓰입니다.
3. **모델 제어**: Jev·Laya·Laya-MLX 중 하나로 실행하고 선택 행동, 매핑 명령, 입력 결과, 다음 상태를 확인합니다.
4. **설정 실험**: 연결 설정의 관찰 주기·상태 유효 시간·입력 시간·행동 매핑을 수정하고 다시 연결합니다. 모델·정책·추가 지연은 실행 설정에서 바꿉니다.
5. **같은 게임의 다른 연결**: 연결 해제 후 반대 제어 경로를 골라 다시 연결합니다. **게임 창 준비**로 띄운 창은 재사용됩니다. 키마의 실제 실행 버튼은 시작할 때 선택한 게임 창으로 한 번 전환합니다. 실시간 게임이 정지 상태라면 게임 창에서 P로 재개하세요. 같은 초기 조건을 비교하려면 게임 창의 N으로 원하는 상황을 고릅니다. 직접 실행한 외부 게임의 attach 연결을 끊어도 그 게임은 종료되지 않습니다.
6. **외부 게임**: [외부 게임 연동](docs/external-games.md)에 따라 키마 관찰기 또는 모드 브리지를 구현합니다. 실제 외부 게임 연결은 [Slay the Spire 2 설치·연결 안내](docs/slay-the-spire-2.md)를 참고하세요.

실시간 게임의 초기 모델 로딩이나 느린 판단은 유효 시간을 초과해 폐기될 수 있습니다. 콘솔에서 폐기 사유와 지연을 보고 조절하세요. 단순히 유효 시간을 늘리면 오래된 판단이 적용될 수 있으므로 결과를 함께 비교합니다.

레이싱·MOBA의 **실시간 시연 시작**은 로컬 모델의 첫 판단을 입력 없이 준비한 뒤, 선택한 시작 상황을 새 판으로 리셋하고 자동 제어를 시작합니다. 기본 구성은 Laya-MLX가 게임을 제어하고 Jev가 같은 관찰을 보고 판단을 비교하는 방식입니다. Jev API 키가 없으면 해당 모델은 호출하지 않고 키 필요 상태를 표시합니다. 제어 모델과 비교 모델은 설정에서 바꿀 수 있습니다.

게임 옆의 **실시간 모델 판단**에서 각 모델의 호출 중 시간, 최근 행동, 실제 응답 시간과 입력 적용 여부를 확인합니다. 게임은 판단 중에도 계속 진행하며, 늦은 입력은 취소합니다. 비교 모델은 게임을 조작하지 않고, 이전 판단이 진행 중이면 새 요청을 중복해서 쌓지 않습니다. 로컬 모델 준비 시간과 실제 플레이 판단 시간은 따로 기록됩니다.

## 연결 방식

| 방식 | 관찰 | 행동 | 용도 |
|---|---|---|---|
| `socket` | 로컬 Unix 소켓으로 구조화 상태 | 게임 행동 명령 | 내장 게임 실행 또는 기존 게임 attach |
| `kbm` | 게임 창 캡처 → 게임별 `observer.py` | 키보드·마우스 매핑 | 게임 코드 수정 없이 연결 |
| `mod` | localhost TCP JSONL로 구조화 상태 | 문자열 또는 구조화 명령 | 외부 게임 모드·플러그인·테스트 훅 |

`app`, `attach`는 인터페이스 프로필 이름입니다. 예를 들어 `app`도 실제 전송은 `socket`을 사용합니다. 버전 선택은 실행 대상이며, 실제 `info.build`와 일치해야 버전 확인으로 표시됩니다.

세 내장 게임 모두 `desktop-v1`에서 두 제어 경로를 지원합니다. **게임 인터페이스**는 게임에 넣은 테스트 훅에서 구조화 상태를 받고 행동 명령을 보냅니다. **화면 + 키마**는 같은 창을 캡처하고 게임별 관찰기로 상태를 읽은 뒤 OS 키 입력을 보냅니다. 내장 관찰기는 화면 하단의 공개 숫자·색상 계기를 읽는 강의용 예제입니다. 일반 게임 화면을 이해하는 범용 비전 모델이 아니며 게임 상태 소켓을 관찰에 사용하지 않습니다. 키마의 입력 전송 성공은 게임의 행동 수락 확인과 구분합니다.

고급 설정에서 `app`을 직접 연결하면 기존처럼 연결 해제 시 그 연결이 실행한 창도 종료됩니다. 두 경로를 같은 창에서 비교하려면 **게임 창 준비** 후 `attach`와 `kbm`을 사용하세요. 제어 경로마다 수정한 입력 매핑·시간 설정은 해당 화면을 열어 둔 동안 유지됩니다.

앱으로 배포하려면 `./build_game.sh`로 세 게임을 포함한 `dist/TeachingLab.app`을 빌드합니다. Finder 실행은 RPG로 시작하며 `open -n dist/TeachingLab.app --args --game moba --socket /tmp/teaching-moba.sock`처럼 게임과 연결 주소를 지정할 수 있습니다. 번들 앱에 키마로 연결할 때는 창 설정의 `owner`를 `TeachingLab`으로 바꿉니다. 소스 실행의 owner는 `python`이며, macOS에 `Python`, `python3`, `python3.12`처럼 표시되는 실행 이름도 인식합니다. 지정한 PID와 창 제목은 계속 확인합니다. 키마 코드를 수정한 뒤 앱 모드로 연결하려면 `./build_kbm.sh`로 다시 빌드하고 콘솔도 다시 실행하세요. 재빌드 후 화면 기록·손쉬운 사용 권한을 다시 허용해야 할 수 있습니다.

내장 게임의 영문 단축키는 macOS 한국어 입력 상태에서도 같은 키 위치로 작동합니다.

키마는 macOS 화면 기록·손쉬운 사용 권한이 필요합니다. `./build_kbm.sh`로 공통 KbmAgent를 빌드할 수 있고, 개발 실행은 콘솔의 `dev`를 사용합니다. 콘솔의 실제 실행 시작 시 연결된 게임 창으로 한 번 전환하고, 이후에는 해당 창이 앞에 있을 때만 입력합니다. 판단 중 다른 앱으로 이동하면 전면을 다시 가져오지 않고 입력을 차단합니다. 분석·비교·DRY-RUN·상태 조회는 창을 전환하지 않습니다. 같은 앱의 창이 여러 개면 창 설정에 대상 `pid`를 지정하세요. 마우스를 화면 왼쪽 위로 옮기면 정지합니다. 새 입력 매핑은 먼저 DRY-RUN으로 확인하세요.

## 코드 위치

```text
games/party, racer, moba/   질문·사례·정책·버전·인터페이스 설정
sims/                      세 게임의 규칙과 기준 행동 계산
gamelab/desktop_game.py     세 게임 공통 게임 창과 실시간 시계
gamelab/game_windows.py     연결 전환 중에도 유지하는 게임 창 수명 관리
gamelab/screens.py          내장 게임의 화면 기반 관찰
gamelab/game_case.py        게임 패키지 로드·검증·연결 선택
gamelab/configuration.py    수정 가능한 연결 설정과 검증
gamelab/socket_game.py      공통 상태/행동 클라이언트
gamelab/protocol.py         Unix/TCP JSONL 전송
gamelab/mod_bridge.py       외부 모드 브리지 작성용 계약
kbm/                       화면 캡처·입력·포커스·유효성 확인
gamelab/decide.py           Jev / Laya / Laya-MLX 호출
gamelab/runner.py           관찰 → 판단 → 입력과 기록·채점
gamelab/console.py          콘솔 세션·모델 작업·연결 상태
gamelab/console_http.py     로컬 HTTP API
web/                       강의 콘솔 화면
examples/external_mod/     실제 TCP 연결 가능한 모드 예제
examples/external_control/ 브라우저 브리지 예제
```

새 게임의 실행 방법을 콘솔이나 러너에 추가하지 않습니다. 외부 게임 폴더의 질문·인터페이스·관찰기와 해당 게임의 브리지만 추가합니다. [설정 파일 안내](games/README.md), [코드 수정 안내](docs/games-guide.md)를 참고하세요.

## CLI와 검증

```sh
uv run python play.py list
uv run python play.py doctor party --version sim-v1
uv run python play.py run party --version desktop-v1 --interface app --provider laya-mlx --steps 3
uv run python -m gamelab.desktop_game --game racer --socket /tmp/lecture-racer.sock
uv run python play.py observe racer --version desktop-v1 --interface attach --socket /tmp/lecture-racer.sock
uv run python -m unittest discover -s tests
node tests/frontend_learning.cjs
node tests/frontend_connections.cjs
node tests/frontend_routes.cjs
```

테스트의 scripted 모델은 연결 회귀 검증용이며, 실제 Jev/Laya 성공을 뜻하지 않습니다.

## Git 관리 범위

이 저장소에는 프로젝트 소스, 게임 설정, 테스트, 실행 가능한 연동 예제와 설치·실행·구조·개발 문서를 관리합니다. 강의 슬라이드, 교안, 워크북, 강의자료 생성 스크립트·이미지·폰트는 로컬에만 보관하고 Git에 올리지 않습니다.

- `docs/teaching/`: 강의자료 원본과 제작 자산
- `output/`, `tmp/pdfs/`: PDF, 캡처, 검증 로그와 임시 생성물

위 경로는 `.gitignore`로 제외합니다. 프로젝트 문서는 강의 진행안이나 개인 작업 기록 대신 재현 가능한 사용법과 구현 정보를 설명합니다. 공유할 검증 결과는 필요한 조건·방법·결과를 프로젝트 문서에 요약합니다.
