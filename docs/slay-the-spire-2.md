# Slay the Spire 2 외부 게임 연동

이 연동은 **Slay the Spire 2**의 게임 상태를 모드로 읽고, GameLab에서 고른 행동을 게임에 전달합니다. Slay the Spire 1의 CommunicationMod와는 다른 경로입니다. 게임 본체와 지원 모드는 별도 설치가 필요합니다.

```text
Slay the Spire 2 + 모드
    ↕ 게임 상태 / 게임 행동
GameLab Slay the Spire 2 브리지
    ↕ localhost TCP JSONL (127.0.0.1:8766)
GameLab 콘솔 또는 play.py → Jev / Laya / Laya-MLX
```

## 현재 제공 범위

- 게임 카탈로그: `slay_the_spire_2`, 타입 `turn.rpg`, 연동 버전 `mod-v1`.
- 연결 방식: 이미 실행한 외부 게임과 브리지에 `mod`로 연결합니다. 게임 창은 보이는 상태로 둡니다.
- 행동 선택: 브리지가 현재 상태에서 후보를 만들면 모델은 `candidate_0`부터 `candidate_63` 중 실제로 제공된 하나를 고릅니다. 같은 번호의 의미는 다음 관찰에서 달라질 수 있습니다.
- 실행 보호: 관찰 당시 상태와 후보가 여전히 유효한지 확인한 뒤 행동을 전달합니다. 없는 후보는 실행하지 않습니다.
- 새 런 시작과 초기화는 자동화하지 않습니다. 사람이 게임에서 런을 준비합니다.

현재 후보로 제공하는 행동은 전투 카드 사용·대상 선택·턴 종료, 이벤트·지도·보상·휴식 선택, 카드 선택 확인, 열린 보물상자의 유물 획득과 다음 화면 진행입니다. 포션 사용과 상점 구매는 현재 자동화 범위에 포함되지 않습니다. 후보가 64개를 넘으면 일부를 임의로 버리지 않고 입력을 막습니다.

`mod-v1`은 이 저장소의 연결 계약 버전입니다. 설치된 게임 패치나 외부 모드의 실제 빌드 버전과 같다는 뜻이 아닙니다. 연결 때 보고되는 게임·모드 정보도 별도로 확인해야 합니다.

## 필요한 모드

[STS2MCP](https://github.com/Gennadiyev/STS2MCP)의 MIT 라이선스 소스를 사용하며, 이 연동의 기준 소스는 커밋 `55e064850a68f3b4cde7e5fd525bf9b2dec4e885`입니다. 외부 모드의 버전은 `0.4.0`이고, GameLab 수정본은 health 응답에 `gamelab_patch: ai-test-v1`을 추가합니다.

**원본 배포 DLL을 그대로 설치하면 이 브리지는 연결을 거부합니다.** 수정본은 상태 읽기가 게임을 진행하지 않도록 하고, 관찰 revision을 게임 스레드에서 확인한 뒤 행동을 처리하도록 보완합니다. 모드 빌드에는 설치된 게임의 참조 파일이 필요합니다.

게임 패치가 바뀌면 같은 모드 소스라도 다시 빌드하거나 동작을 재검증해야 할 수 있습니다. 이 연동은 현재 설치된 게임의 실제 실행 결과로 호환성을 확인하며, 브리지 버전 일치만으로 호환성을 판단하지 않습니다.

설치 파일을 새로 만들 때는 다음 순서로 진행합니다.

1. .NET 9 SDK를 준비합니다. 수정 소스와 빌드 절차는 [모드 빌드 레시피](../integrations/slay_the_spire_2/README.md)에 있습니다.
2. 프로젝트 루트에서 설치된 게임 파일을 참조해 빌드합니다. `--output`에는 아직 없는 디렉터리를 지정합니다.

   ```sh
   python3 integrations/slay_the_spire_2/build_mod.py \
     --dotnet dotnet \
     --game-data "$HOME/Library/Application Support/Steam/steamapps/common/Slay the Spire 2/SlayTheSpire2.app/Contents/Resources/data_sts2_macos_arm64" \
     --output /private/tmp/ai-test-sts2-mod-package
   ```

   이 세션에서 준비한 SDK를 쓸 때는 `--dotnet /private/tmp/ai-test-dotnet9/dotnet`으로 바꿉니다. SDK 위치는 이 컴퓨터의 임시 설치 경로입니다. 빌드 도구는 고정 커밋을 가져와 패치를 적용하며 게임 파일을 수정하지 않습니다.

3. 게임을 종료한 뒤, 출력 폴더의 `STS2_MCP.dll`과 `STS2_MCP.json` 두 파일을 `<Steam 게임 폴더>/SlayTheSpire2.app/Contents/MacOS/mods/`에 직접 넣습니다. 기존 동명 파일이 있으면 원본을 보관하고 교체합니다.
4. 게임을 다시 실행하고 게임이 표시하는 모드 사용 동의 화면을 확인합니다. 게임 모드 서버가 기본 포트 `15526`에서 응답하면 아래 연결 절차로 진행합니다.

빌드 결과의 `provenance.json`은 소스 커밋·패치·참조 게임 파일의 정보를 기록합니다. 설치 파일과 함께 보관하면 어떤 버전을 검증했는지 추적할 수 있습니다. 제거할 때는 게임을 닫고 이번 연동의 `STS2_MCP` 파일만 제거합니다.

## 연결 순서

지원 모드를 설치한 게임을 먼저 실행하고, 사람이 새 런 또는 이어할 런을 준비합니다. 아래 명령은 프로젝트 루트에서 실행합니다.

1. 게임 상태를 읽기 전에 모드 서버와 수정 버전을 확인합니다.

   ```sh
   .venv/bin/python -m gamelab.slay_the_spire_2 --probe
   ```

2. 별도 터미널에서 브리지를 실행하고 계속 켜 둡니다.

   ```sh
   .venv/bin/python -m gamelab.slay_the_spire_2 \
     --api-url http://127.0.0.1:15526 --port 8766
   ```

   게임 모드의 HTTP 서버는 `15526`, GameLab이 접속하는 TCP 서버는 `8766`입니다. 둘은 다른 포트입니다. 이 게임에는 Slay the Spire 1의 표준입출력 `ready` 핸드셰이크를 사용하지 않습니다.

3. 다른 터미널에서 연결과 현재 상태를 확인합니다.

   ```sh
   .venv/bin/python play.py doctor slay_the_spire_2 --interface mod
   .venv/bin/python play.py observe slay_the_spire_2 --interface mod
   ```

   게임 화면의 체력·에너지·손패·적과 출력 상태를 비교합니다. `candidates`의 `key`와 `label`도 확인합니다. 메인 메뉴·적 턴·미지원 화면처럼 후보가 없는 상태에서는 관찰이 `ok:false`와 사유를 반환하며 모델 호출을 막습니다. `blocked_reason`이 있으면 해당 상태를 해결한 뒤 다시 관찰합니다.

4. 모델로 행동을 한 번 적용합니다. 이 명령은 실제 게임을 조작합니다.

   ```sh
   .venv/bin/python play.py run slay_the_spire_2 \
     --interface mod --provider laya-mlx --no-shadow --steps 1
   ```

   Jev를 사용할 때는 해당 API 키를 환경 변수에 설정한 뒤 `--provider jev`로 바꿉니다. 게임 화면에서 선택한 행동과 결과를 확인한 뒤에만 `--steps`를 늘립니다. 이 `mod` 연결에는 키보드·마우스 전용 `--dry-run`을 쓰지 않습니다.

웹 콘솔에서도 게임 **Slay the Spire 2**, 버전 **mod-v1**, 인터페이스 **mod**를 선택하면 같은 브리지로 연결됩니다. 콘솔을 열기 전에 게임과 브리지를 준비해야 합니다.

## 사용 시 주의할 동작

모델 제어 중에는 마우스·키보드로 게임을 동시에 조작하지 마세요. 지원 모드는 게임 스레드에서 관찰 revision을 확인한 뒤 행동을 처리합니다. 오래된 관찰로 고른 행동은 다시 관찰해야 하며, 실제 설치 빌드에서 이 보호가 작동하는지도 검증해야 합니다.

이 연동은 `gamelab_patch: ai-test-v1`을 보고하는 수정 모드를 요구합니다. 수정 모드는 상태 조회에서 게임 UI를 자동 진행하지 않도록 하고, 행동 요청에 revision 검사를 추가합니다. 원본 모드는 일부 상점·보물상자 상태 조회 중 UI를 진행할 수 있어 브리지가 상태 조회 전에 거부합니다. `--probe`는 게임 상태를 조회하지 않고 모드 서버의 health 응답만 확인합니다.

상점이나 보물상자 화면을 여는 동작은 사람이 먼저 수행해야 합니다. 자동으로 열리지 않는 상태에서 후보가 없으면 실행을 멈추고 필요한 화면을 연 뒤 다시 관찰합니다.

GameLab 연결을 끊는 것과 게임을 종료하는 것은 별개입니다. attach 세션을 끝내도 게임을 종료하거나 새 런으로 초기화하지 않습니다. 다시 연결할 때는 현재 게임 화면과 상태부터 확인하세요.

## 검증 결과를 읽는 법

| 확인 항목 | 입증하는 것 |
|---|---|
| 카탈로그 로드 | 질문 64개와 행동 매핑, 인터페이스 설정의 형식이 맞음 |
| 합성 상태·가짜 모드 테스트 | 프로토콜 변환과 오류 처리가 해당 예시에서 동작함 |
| 실제 모드 서버 응답 | 설치한 모드에 연결할 수 있음 |
| 실제 게임 상태와 화면 비교 | 읽어 온 상태가 현재 게임과 일치함 |
| 실제 모델 행동과 게임 변화 | 모델 선택이 게임에 적용되고 예상한 상태 변화가 일어남 |

앞 단계만 통과한 결과를 실제 게임 플레이 완료로 판단하지 않습니다. 실제 게임 창·모드 빌드·모델 행동을 함께 확인해야 합니다.

`games/slay_the_spire_2/cases.json`은 후보 선택 형식을 설명하는 직접 작성한 합성 예시이며 `truth`는 `null`입니다. 실제 게임 기록이나 공식 최적 행동이 아니므로 정답률이나 모델 성능의 근거로 사용하지 않습니다.
